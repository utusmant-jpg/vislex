## F01 — new backup regression: a real transcript can make its backup unrestorable

**Static confidence: high. Priority: P0. Task: R01.**

Source: `src-tauri/src/transcription.rs::publish` and `backup.rs::{prepare_backup,write_archive,restore}`; regression-test gap in `src-tauri/tests/backup_artifacts.rs`.

The transcript publisher registers all generated files in the artifacts table, including working/transcripts TXT, JSON and SRT. Backup first includes every registered artifact path. The added directory scan then includes the same transcript files again. The writer iterates both lists. Restore opens each file with create_new, so a repeated path is rejected.

The new test manually writes transcript files but never registers those paths as the real publisher does. It therefore tests a different state and can pass while actual transcript backups fail. The old ledger explanation that transcript files were never backed up was mistaken: registered transcript files were already included through artifacts.

Model reproduction: three registered transcript paths plus the same directory scan gives six archive entries but three unique paths; exclusive create fails on the second instance. This was modeled locally, not run through Rust/age.

Fix one canonical path/hash manifest. Preserve duplicate-entry rejection, PDF support and legacy restoration. Test actual transcription::publish using valid synthetic output, then encrypt/restore/reopen. Do not 'fix' it by allowing archive overwrites. Also test symlinks/reparse points: the added scan uses following metadata without a dedicated path-containment check. Future manifest versions must not be silently ignored.

## F02 — new historical locator support validates the wrong revision

**Static confidence: high. Priority: P0. Task: R02.**

Sources: `case.rs::{publish_extract,read_text,read_text_revision,validate_citation}`, `evidence.rs::EvidenceLocator::Text`, `bridge.ts::citationParts`, `markdown.tsx`, `EvidenceViewer.tsx`; tests `extract_revisions.rs`.

Schema 6 is progress: full transcript activation replaces the old partial in search and retains prior wording. However, emitted #L locators still contain no extraction revision. validate_citation uses active read_text. The typed text locator checks that a specified revision exists and then delegates bounds to the same active-text validator.

Consequences: a valid old interval can fail if new text is shorter; a nonexistent old interval can pass if new text is longer; the same ordinary citation can display different wording after a new extraction. Existence of a history row is not an end-to-end history contract.

The historical reader also needs bounded payloads, provenance and a resolvable locator. The migration test creates schema 6, lowers user_version and reopens it without removing the new table; that does not test a real pre-schema-6 database.

Use one versioned locator grammar/resolver shared by source reads, UI hover/open/copy, structured objects, search, agents, coverage and exports. Preserve legacy citations only with justified recorded provenance; otherwise display legacy ambiguity, never guess a revision. Test actual old schema and both directions of line-count changes.

## F03 — new assertion heuristic accepts non-equivalent statements

**Static confidence: high. Priority: P0/P1. Task: R03.**

Sources: `dossier.rs::{content_tokens,is_qualifier,completion}`, `tests/dossier.rs::sentences_citing_mapped_dossier_evidence_count_as_represented` and related new tests.

The heuristic drops `not` and numeric-only tokens. It skips short sentences, bypasses a whole sentence containing broad qualifier substrings, or accepts a sentence carrying a citation already used by a dossier claim. It splits at periods, including decimal/timestamp punctuation. These are not semantic support checks.

Concrete counterexamples: 'The officer was armed' versus 'The officer was not armed'; 'Officer Smith found 2 bags' versus 'Officer Smith found 200 bags'. Existing mapped citations can accompany unrelated assertions. The new test actually expects such a cited instrument-log assertion to count as represented.

This does not prove that the whole completion function always emits complete: other independent review/coverage gates still apply. It proves that this supposed final-prose coverage gate can be bypassed by unsupported additions when its other prerequisites are met.

Do not replace the threshold with another threshold or a stronger prompt. Make new factual assertions explicit stable blocks, bind them to claim/evidence revisions and review stamps, and render reviewed fact wording from the structured document. New wording is a new candidate. Free prose remains usable but unreviewed. AI assessment and human acceptance remain separate, neither guarantees truth.

## F05 — automatic review currentness and once-only completion are incomplete

**Static confidence: high for fingerprint/audit paths; runtime race behavior requires a test. Priority: P1. Task: R05.**

Source: `automatic.rs::{start_review,status,preempt_for_chat}`, `desktop.rs::run_session`, corresponding `core.rs` tests.

The completion fingerprint is now written after completion, but represents sorted source IDs/hashes rather than the extraction and discovery revisions actually available. A better transcript or new visual index for the same source may not trigger a new review. Actual preemption also crosses an in-flight transport cancellation path; direct database state changes in tests do not establish real coordinator race behavior. Use typed transitions, epochs, explicit partial completion and a controllable fake provider for ordering tests. Never replay uncertain requests merely to make automatic resume convenient.
