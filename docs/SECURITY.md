# Security boundaries of this development build

The Rust coordinator owns case state and database writes. The UI invokes case operations and receives source content through an allowlisted custom protocol. It cannot invoke an unrestricted shell or arbitrary filesystem tool. Model function names/arguments are validated against task mode, selected sources/records, current restrictions, file protection and revision base.

Windows workers run in a newly created AppContainer with no capabilities and no inherited handles. A suspended process is assigned to a Job Object before resuming. The package is granted read/execute access; a private per-job directory is granted write access. The original source and database are not granted to the worker. The job terminates on timeout, excessive memory or coordinator teardown; child process creation is restricted. Temporary grants/profile cleanup are attempted through RAII. Sandbox creation failure is fatal rather than falling back to unsandboxed parsing.

AppContainer is not a claim that every Windows-readable object is inaccessible. Tests cover a private external file, attempted modification, loopback networking and actual parser execution. They do not constitute an independent sandbox audit. Runtime ACL provisioning on a clean installation remains to be verified. Job manifests replace the planned pipe transport in this version.

Imported text, metadata, HTML-like text, processor outputs and model responses are untrusted data. React renders strings as text. No HTML evidence execution, remote image loading in emails, macros, formula evaluation, arbitrary code execution, model-controlled destinations or agent evidence deletion is implemented. Unsupported structures remain unsupported, not silently claimed as reviewed.

Application API destinations are the four native provider adapters — OpenAI Responses, Anthropic Messages, Google Gemini generateContent, and xAI Grok's Responses-compatible endpoint — plus each provider's model-list endpoint used by app settings to load the model catalogue. Provider requests refuse redirects. Keys use Windows Credential Manager (one entry per provider) and are not stored in cases, backups, the renderer or worker environment; applying app-wide AI preferences to a case copies no credentials. Cases default to offline and disallow text/image transmission; the app-wide preferences enable transmission when applied to a case. Offline and source restrictions are checked before preparing requests; UI cancellation is checked while waiting for the network. There is no updater, runtime model download or telemetry. Beyond the provider APIs, the only network fetch is the explicit public-authority retrieval adapter: HTTPS-only URLs without credentials, custom ports or fragments; a fixed host allowlist (courtlistener.com, govinfo.gov, supremecourt.gov with their www forms; uscode.house.gov; www.uscourts.gov; www.ecfr.gov); redirects refused; a 45-second timeout; an 8 MiB response cap; and a text/plain, text/html or application/pdf MIME allowlist. That retrieval sends no case text, credentials or cookies; the downloaded bytes are hashed and imported as an immutable source. WebView2/OS network behavior needs a full offline packet-capture acceptance test; no claim of system-wide network isolation is made.

The optional ChatGPT-subscription sidecar (built only with the `subscription` feature) runs in its own AppContainer with the `internetClient` capability and no host allowlist; the coordinator confines it to namespaced case tools, but its network egress is not restricted by host. The optional research browser (built only with the `research` feature, off by default) is a child webview inside the main window that the user signs into; its traffic goes directly from WebView2 to the sites it loads. It has its own WebView2 profile outside every case folder, which holds the site session and must be treated as a secret store; after creation the app confirms WebView2 actually uses that profile. Isolation from the application: Tauri capabilities are scoped to the `main` webview only; the app `command` rejects calls from any webview other than `main` (the app has no command ACL manifest, so Tauri alone would admit a local-origin frame); the application UI sends `frame-ancestors 'none'`; and the `evidence` protocol serves only the `main` webview. Tauri still injects its IPC globals into the research page, so sites can detect the embedding. The pane refuses to open while WebView2 browser arguments contain a debugging or `user-data-dir` switch, while `WEBVIEW2_USER_DATA_FOLDER`, `WEBVIEW2_PIPE_FOR_SCRIPT_DEBUGGER` or `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` is set, or while WebView2 `AdditionalBrowserArguments`/`UserDataFolder` registry policies are present or unreadable; WebView2 exposes no reliable way to detect an active DevTools listener after creation. The only exception is debug test mode against a loopback fixture. Top-level navigation is limited to exact https research and sign-on hosts; iframe navigations are not filtered by that allowlist. The research browser is switched on per case (revisioned and audited; never by app-wide preferences; refused while offline). Its agent tools are offered only to chats the user starts in Investigate mode, never to background review or team assignments, and only on the API-key route until the subscription route's persistence probe passes. Browser actions run outside the case lock and are checked in Rust first: the agent may navigate only to research hosts (re-checked after load), type only into search or filter fields and never while a password or verification field is on the page, and may not use delivery, download, sharing, account or site-AI controls. Per-task limits cap pages, queries and typed characters, and a minimum interval paces navigation. Every query text and navigation is written to the case audit log before it runs. Page content returned to the model is marked as untrusted data; page JavaScript is never built from model text. Debug test mode opens only a loopback fixture, never the user's real research profile, and cases only under VISLEX_TEST_CASE_ROOT.

Research captures (R46–R47) store only the sanitised opinion region of a page as HTML: scripts, hidden inputs, event handlers, `data:` and `javascript:` URLs and the site playbook's editorial regions are removed. The full page is hashed for provenance and never stored. Each capture is published as an immutable source with an R1 extract; the task's scope grows to include it only for the task that captured it. The authority object created with it stays unreviewed until a human cite-check: the backend refuses acceptance unless all four checks (exists, quote, citator, support) are recorded, and records them as `cite_check` in the `evidence_review` audit. Work products copy only a whitelisted projection of an authority. Research page text returned to the model is not kept past the turn. The audit log records `research_page_opened`, `research_capture_requested`, `research_capture_published` and `task_scope_expanded`. Capture refuses on sites whose playbook has no content region; the Westlaw entry has none until the R36 selector map, so capture is not yet available on real Westlaw.

API `store:false` is not a zero-retention guarantee. Permissions currently operate at source level, not selected-region/redacted-payload granularity. Reservations persist after ambiguous API failures, and the app does not retry those tasks blindly. Conservative token allowances and supplied rates are not exact provider billing limits. Usage reconciliation and provider-model capability certification remain outstanding.

Originals use hashes and read-only filesystem flags. Working data is OS-protected plaintext. Hash-linked audit entries detect straightforward local changes but are not tamper-proof custody or proof of evidence authenticity. An OS administrator can alter data, binaries and audit histories.

Backups use age passphrase encryption over a consistent database snapshot and hashed artifact inventory. Restoration rejects unsafe paths, nonregular members, duplicate entries, hash mismatches and malformed/incomplete encrypted streams. Backup contents include restricted evidence and old revisions.

Exports have distinct boundaries. Record text/JSON and PDF/DOCX document drafts carry their draft and review status; they are not sanitized disclosure packages. A reviewed dossier bundle includes cited source copies and a manifest explicitly marked `redacted: false`; human acceptance of findings does not sanitize those copies. A flattened redaction PDF can be exported only after page-specific human review of the exact derivative and a fresh hash/restriction check at publication. That check does not discover every sensitive region or certify the reviewer's boxes. Tests inspect synthetic output bytes for hidden PDF text, attachments and metadata, but full visual disclosure review remains a human task.

Before public use: independent security assessment, dependency/license review, signed distribution, adversarial parser/agent fixtures, strict-offline observation, leak checks and restore verification on a separate machine are required.
